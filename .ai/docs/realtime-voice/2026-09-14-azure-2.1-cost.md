# Azure 2.1 cost accuracy

The user reported unknown cost for the working `gpt-realtime-2.1` deployment and requested the most accurate provider-backed accounting available.

Azure's [Realtime reference](https://learn.microsoft.com/en-us/azure/foundry/openai/realtime-audio-reference) delegates to the [Realtime API reference](https://developers.openai.com/api/docs/api-reference/realtime-server-events/response/done). Response usage contains input/output totals, per-modality counts, and cached-input totals/details. It does not document a returned dollar charge or a separate cache-write counter. Cached input is explicitly a subset of input. Reasoning tokens are not added a second time to the reported output text count. No speculative cost field or cache-write surcharge was introduced.

Queried the public Azure Retail Prices API, restricted to exact 2.1 meter prefixes, East US 2, and Consumption pricing. All 16 Global/Data Zone rows fit one page with no continuation. The eight Global Standard USD meters are retained in `.ai/validation/azure-realtime-2.1-pricing.json`:

| Modality | Input / million | Cached input / million | Output / million |
| --- | ---: | ---: | ---: |
| Text | $4 | $0.40 | $24 |
| Audio | $32 | $0.40 | $64 |
| Image | $5 | $0.50 | Not priced |

Added the explicit model entry; existing historical repricing now recovers previously unknown 2.1 observations without rewriting history. New response observations reconcile input/output/total/cache totals and modality breakdowns before pricing. Missing or inconsistent details remain unknown/partial rather than silently becoming zero-cost usage. The normalizer does not assign a guessed modality to aggregate cache tokens.

Tests cover every retained Azure meter, mixed text/audio/image cache billing, full precision, historical repricing, and incomplete/inconsistent usage. The mixed fixture calculates $0.03569 and displays `$0.0357 (api)`.

Limitations: these are Global Standard list estimates, not returned invoice charges. The deployment billing SKU and negotiated rates cannot be established from the Realtime usage response or the resource API key; Data Zone rates differ. Existing recorded observations cannot reconstruct raw detail that was never persisted. Separate transcription usage remains excluded under the existing policy. Reassess the rate table when Azure changes meters or a different billing tier is selected. A live text-only 2.1 response completed in approximately two seconds and returned 0 input tokens, 5 text output tokens, and no monetary-cost field. The parser accepted the complete breakdown and calculated $0.00012 from Azure's published text-output rate. The socket closed immediately in `finally`; no audio was sent or generated. These are the provider's reported counts, not locally estimated prompt tokens.
